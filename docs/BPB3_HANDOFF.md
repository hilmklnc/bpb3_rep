# BayesPI-BAR / bpb3 benchmark handoff

Last verified: 2026-11-11. This handoff preserves the completed 67-variant
benchmark reconstruction and prepares an explicit interface for predictions
generated by bindFx outside this repository. It does **not** contain invented
bindFx predictions and does **not** reduce the benchmark to TFs currently
covered by bindFx.

## 1. Scientific purpose and evidence boundaries

The project has two related goals:

1. Reconstruct the 2015 BayesPI-BAR evaluation of 67 experimentally supported
   regulatory mutations, including the BayesPI-BAR, sTRAP, and is-rSNP curves
   in Figure 6.
2. Compare externally generated bindFx mutation-effect predictions with the
   experimental TF/effect annotations, while keeping TF retrieval/ranking
   separate from binding-effect direction agreement.

The repository uses these evidence classes:

- **Experimental observation:** TF/motif and gain/loss/unknown annotations in
  the BayesPI-BAR author workbook, with a per-record PubMed ID. These are
  author-curated experimental claims; the 70 underlying primary assays have
  not been independently re-reviewed here.
- **Original published prediction:** rows recovered from the author-archived
  comparative ranking files used by the 2015 paper. The sTRAP and is-rSNP rows
  are the paper authors' comparison outputs, not fresh runs from independently
  obtained official software.
- **Reproduced computational result:** tables and plots calculated locally
  from those archived rows. These are not new BayesPI-BAR predictions.
- **Repository annotation:** FASTA labels, group membership, and broad aliases
  in bpb3 source code. These are useful for replication but are not primary
  experimental evidence.
- **Unavailable or unverified:** genome coordinates/builds, explicit assay
  types, primary-article verification, BayesPI-BAR2/bpb3 variant-level results,
  and any real bindFx predictions.

## 2. Benchmark data

### Origins and identifiers

The 67 paired sequences come from
`final_demo_data/demo1_67snps/in/snps_ref.fasta` and `snps_alt.fasta` in the
original bpb3 repository. Every record is 61 bp and has exactly one central
substitution at zero-based offset 30. Group membership is 4 Fredriksson, 29
HGMD, and 34 Andersen/Epstein records.

The author archive `Mutations.tar.gz` supplies `All Mutations.xlsx`, from which
`benchmark/data/variants_67.tsv` and `experimental_tf_effects.tsv` were parsed.
The mutation table has 47 dbSNP rsIDs and 57 HGMD IDs. The stable internal key
is `benchmark_id` (`BPB3_67_001` through `BPB3_67_067`); repository labels and
rsIDs are not complete substitutes for it.

No genome assembly, chromosome, or genomic coordinate was established for any
of the 67 records. Those columns are intentionally blank. They must not be
filled by assuming hg19 merely because other bpb3 demos contain hg19 assets.
Coordinate-based bindFx exports require independent assembly/allele
normalization before coordinates can be treated as verified.

The workbook nucleotide-change orientation agrees with the paired FASTAs for
65/67 records. Two are reversed:

- `ITGA2_SP1|LOSS`: workbook `C -> T`; FASTA `T -> C`.
- `F9_C/EBP|LOSS`: workbook `G -> C`; FASTA `C -> G`.

The paired FASTA orientation is the canonical computational orientation used
by the integration script. Experimental-direction interpretation for these two
records remains an explicit caveat.

### Core table schemas

`variants_67.tsv` is one row per sequence pair. Important columns are
`benchmark_id`, `repository_label`, `gene`, `rsid`, `hgmd_id`,
`published_nucleotide_change`, `sequence_nucleotide_change`,
`allele_order_match`, `ref_sequence`, `alt_sequence`, `variant_offset_0based`,
`ref_allele`, `alt_allele`, and provenance/verification fields. The
`genome_build`, `chrom`, and `position_1based` fields are currently blank.

`experimental_tf_effects.tsv` is one row per reported TF/motif effect. It has
70 rows because three variants report two factors. The effect counts are 23
Gain, 31 Loss, and 16 Unknown. Important columns are `benchmark_id`,
`observation_index`, the raw and normalized TF/motif labels,
`effect_reported`, `reference_pubmed_id`, and evidence fields.

`published_predictions.tsv` contains 16,000 author-archived prediction rows:
4,743 BayesPI-BAR, 6,700 sTRAP, and 4,557 is-rSNP. Important columns are:

- `benchmark_id`, `method`, and `model_or_tf`: variant, method, and PWM/model.
- `predicted_change`: the Positive or Negative ranking side.
- `rank_within_change`: rank within that side, not a single combined rank.
- `score`: the integrated/PCA-derived method score. Its sign is not the
  biological direction label and can have an arbitrary orientation/offset.
- `mean_ddba_or_method_value`: BayesPI-BAR mean delta-dbA or the corresponding
  archived comparison-method value. BayesPI-BAR used mean delta-dbA sign to
  assign the Positive/Negative side.
- `median_p_reference` and `median_p_alternate`: median dbA p-values across
  chemical potentials for the reference and alternate alleles.
- provenance and availability columns: evidence class, repository, commit,
  archive checksum, and recovery status.

The raw score, mean value, and p-value columns were retained for provenance;
Figure 6 uses the archived change side, rank, and model label.

## 3. Original Figure 6 reconstruction

The matching rules in `benchmark/scripts/reproduce_figure6.py` are transcribed
from `code/r/accuracy.R` in the original BayesPI-BAR demo archive. Each archived
prediction row is a PWM/model, not necessarily a unique TF gene. Positive and
Negative lists are ranked independently, so each side can contain rank 1.

For a variant and method, the original analysis:

1. parses the experimentally implicated TF(s) from the repository label;
2. expands each target with the paper's curated regular-expression aliases;
3. matches all accepted PWM/model labels;
4. selects the minimum matching rank rather than averaging PWMs; and
5. treats no match or rank above 50 as rank 51 in pairwise panels C/D.

Some rules are broad (for example, GATA family matches), so the historical
evaluation is not equivalent to exact gene-symbol matching. Multiple reported
TFs for one mutation are effectively alternatives, and the best qualifying
rank gives the variant's result.

### Metrics and reproduced results

Panel A ignores predicted direction and uses all 67 variants. Cumulative
accuracy at cutoff K is the fraction for which an accepted true-TF model has
rank <= K. Panel B requires the correct Positive side for experimental Gain or
the Negative side for Loss. Sixteen unknown-direction observations correspond
to 16 variants and are omitted, leaving 51 variants.

| Method | Panel A Top-10 | Panel A Top-50 | Panel B Top-10 | Panel B Top-50 |
|---|---:|---:|---:|---:|
| BayesPI-BAR | 47/67 | 54/67 | 29/51 | 35/51 |
| sTRAP | 41/67 | 51/67 | 27/51 | 33/51 |
| is-rSNP | 34/67 | 47/67 | 22/51 | 30/51 |

Panels C/D use the direction-agnostic ranks capped at 51. BayesPI-BAR has a
lower rank than sTRAP for 28/67 (41.8%, reported as 42%), while sTRAP is lower
for 14/67 (20.9%, 21%). BayesPI-BAR is lower than is-rSNP for 30/67 (44.8%,
45%), while is-rSNP is lower for 11/67 (16.4%, 16%). The plot annotates the
paper's one-sided paired Wilcoxon signed-rank p-values, 0.015 and 0.00078; the
Python reconstruction does not recompute those p-values.

The numerical products are `figure6_best_ranks.tsv`,
`figure6_cumulative_accuracy.tsv`, and `figure6_pairwise_ranks.tsv`. The
regenerated visualization is `benchmark/reports/figure6_reconstruction.png`.

### Interpretation limits

- Candidate TF/PWM universes differ substantially across methods.
- Selecting the best of several PWMs can favor a larger or more redundant
  model collection.
- Broad family aliases answer a different question from exact TF retrieval.
- Panel B combines TF retrieval and correct direction; it is not a pure
  direction-concordance statistic.
- The workbook evidence is not a substitute for independent primary-assay
  review.

## 4. Previous original-workflow verification

The original paired-FASTA `bpb3 bayespi_bar` path was successfully executed on
one mutation and three unmodified SP1 PWMs, using all six original chemical
potentials and 100 rather than 10,000 shuffles. It completed dbA scoring,
delta-dbA, mean/PCA integration, and ranking in 0.508 seconds with exit status
0. This was a smoke test, not a benchmark-quality reproduction. Exact command,
outputs, hashes, runtime versions, errors, and untested components are retained
in `benchmark/reports/original_workflow_verification.md`.

Bedtools is not called once paired FASTAs are supplied, so bedtools 2.31.1
cannot affect that prediction path. Upstream sequence/background construction
can be version-sensitive. Basic 2.31.1 coordinate microtests passed, but no
side-by-side 2.30.0 comparison was completed. The full 67 variants x 1,772 PWMs
x 10,000 shuffles run remains untested in this work.

## 5. bindFx comparison decisions

The primary scientific principles are:

- Keep TF retrieval/ranking and binding-direction concordance as separate
  outcomes.
- Retain all 67 variants and all 70 experimental observations in audit output.
  Missing models/predictions are statuses, not silently discarded rows.
- Report both all-record and covered-only denominators, and both observation-
  and unique-variant-level results.
- Use exact gene symbols and established aliases for the primary comparison.
  Family/motif matches are a separately labelled sensitivity analysis.
- Do not reuse the historical broad regex aliases silently for bindFx.
- Do not compare raw Top-K rates without reporting each method's candidate TF
  universe and, where possible, a harmonized-universe sensitivity analysis.
- Do not infer a ΔB direction convention. It must be declared at evaluation
  time.

The user-supplied 403-model summary was previously reviewed. The resulting
mapping table and audit are preserved, including unavailable concepts and
family-level candidates. The optional `bindfx_benchmark_strict_38.tsv` is a
historical convenience table only; it must **not** replace the 67-variant input
or define the denominator before predictions are imported.

Current reviewed overlap (not a prediction result): 18 primary TF concepts,
39 TF-effect observations across 38 variants, of which 34 observations across
33 variants have known direction. The broader family/motif sensitivity mapping
contains 25 concepts and 31 possible bindFx models across 55 variants. These
counts describe model-name compatibility, not performance.

## 6. bindFx prediction integration specification

### Input

Export a tab-separated file with the header in
`benchmark/schemas/bindfx_predictions.tsv`. Required columns are:

| Column | Requirement |
|---|---|
| `benchmark_id` | Stable `BPB3_67_NNN` key. Unknown keys are audited and excluded from metrics. |
| `chrom` | Chromosome used by bindFx; may be blank because benchmark coordinates are unverified. |
| `position_1based` | One-based position used by bindFx; may be blank for the same reason. |
| `ref`, `alt` | Alleles in paired-FASTA computational orientation; validated against `variants_67.tsv`. |
| `tf` | bindFx gene/model TF identifier. Use the model inventory symbol where possible. |
| `delta_b` | Signed bindFx mutation effect. Must be finite. |
| `rank_score` | Direction-independent score to rank candidate TFs within a variant; larger means stronger. |

Optional but recommended columns are `model_id`, `p_value`, and `q_value`.
Additional columns are permitted and retained in the raw input audit. If bindFx
uses absolute ΔB as its natural TF-ranking score, export `rank_score=abs(ΔB)`;
otherwise export the method's prespecified ranking statistic. Do not choose a
ranking score after viewing experimental labels.

The evaluator requires `--positive-means gain` or `--positive-means loss`.
This makes the biological interpretation of positive ΔB explicit.

### TF normalization and matching

The evaluator only trims whitespace and uppercases bindFx TF identifiers. It
does not infer aliases or paralogs. Experimental labels are connected to bindFx
symbols through the reviewed
`benchmark/data/bindfx_experimental_tf_overlap.tsv` table. `--mapping-mode
primary` accepts exact genes and established aliases; `primary-and-family`
adds the explicitly documented family/motif candidates as a sensitivity run.

Every non-exact mapping must remain reviewable in the mapping table. Do not map
an unavailable TF to a convenient paralog. A TF model missing from the export
is reported as `eligible_model_not_predicted`; a concept without an eligible
model is `no_eligible_model_under_mapping_mode`.

### Duplicates and unmatched records

One row per variant–TF is preferred. Duplicate variant–TF rows cause an error
by default. If multiple bindFx models intentionally represent one TF, select a
prespecified policy:

- `--duplicate-policy best-rank-score`: retain the largest ranking score.
- `--duplicate-policy mean`: average ΔB and ranking score.

Both are sensitivity choices and must be reported; best-of-model selection can
inflate performance. Unknown variant IDs, reversed/mismatched alleles, and
blank TF identifiers remain in `bindfx_input_audit.tsv` but are not evaluated.

### Ranking, direction, and outputs

TFs are ranked within each variant by descending `rank_score` with competition
ranks for ties. For each experimental observation, an accepted TF match gives
its rank, predicted direction from ΔB, and direction agreement. For family
mappings with multiple candidates, the minimum candidate rank is used and the
matched candidate is recorded.

The evaluator writes:

- `bindfx_input_audit.tsv`: every supplied row and validation status.
- `bindfx_predictions_normalized.tsv`: valid, duplicate-resolved predictions
  with within-variant ranks.
- `bindfx_observation_evaluation.tsv`: all 70 experimental observations,
  including missing/unavailable statuses.
- `bindfx_cumulative_accuracy.tsv`: cutoffs 1–50 for observation and variant
  units, with all-record and covered-only denominators.
- `bindfx_evaluation_summary.tsv`: Top-1/5/10/50 subset of the curves.

Variant-level direction-aware accuracy mirrors the Figure 6 question: a
variant succeeds at K if any experimentally supported TF with a known effect is
ranked <= K and has the correct sign. Observation-level results avoid hiding
multi-TF records. Always report coverage beside covered-only accuracy.

Example command, after placing real predictions locally:

```bash
python benchmark/scripts/evaluate_bindfx_predictions.py \
  --predictions /path/to/bindfx_predictions.tsv \
  --positive-means gain \
  --mapping-mode primary \
  --duplicate-policy error \
  --output-dir benchmark/results/bindfx-primary
```

The command above illustrates the interface; `positive-means gain` must be
changed if that is not the bindFx convention.

## 7. macOS and PyCharm setup

The benchmark-table reconstruction uses Python's standard library. Matplotlib
is needed only for plotting. A recent macOS Python 3.10–3.12 is suitable for
these scripts; the original bpb3 scientific environment remains separately
pinned to Python 3.9.

```bash
git clone https://github.com/hilmklnc/bpb3_rep.git
cd bpb3_rep
git switch handoff/bpb3-benchmark-local

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r benchmark/requirements.txt
```

In PyCharm, open the repository root and select `.venv/bin/python` as the
project interpreter. Set the working directory to the repository root. The
benchmark scripts resolve repository-relative paths from their own locations;
they contain no cloud-workspace path dependency.

Do not use the root `requirements.txt` with pip: it uses conda-style
`name=version` syntax. `environment.yml` documents the original Python 3.9
bpb3 environment and includes bedtools, but some exact packages are
platform-specific and it may not solve unchanged on Apple Silicon. The
repository contains both Linux and Intel (`x86_64`) macOS
`bayesPI_affinity` binaries and selects by platform. The macOS binary was not
tested here and may require Rosetta on Apple Silicon. None of these components
is required to reconstruct Figure 6 or evaluate an already generated bindFx
TSV.

### Reproduce and validate committed results

```bash
python benchmark/scripts/verify_handoff.py
python benchmark/scripts/validate_benchmark.py
python benchmark/scripts/reproduce_figure6.py
python benchmark/scripts/plot_figure6_reconstruction.py
```

Expected validation includes 67 variants, 70 experimental rows, 16,000
prediction rows, Panel A BayesPI-BAR Top-10 47/67, and Panel B Top-10 29/51.

The parsed tables and Figure 6 numerical results are committed, so network
access is not required for these four commands. To rebuild the three source
tables from the author archives:

```bash
bash benchmark/scripts/fetch_published_sources.sh
python benchmark/scripts/build_benchmark_tables.py \
  --mutations-archive benchmark/cache/BayesPI-BAR/Mutations.tar.gz \
  --rankings-archive benchmark/cache/BayesPI-BAR/rankings.tar.gz
python benchmark/scripts/validate_benchmark.py
```

Downloads are checksum-verified. `benchmark/cache/` and generated
`benchmark/results/` are Git-ignored.
